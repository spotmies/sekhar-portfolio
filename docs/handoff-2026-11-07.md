### AssemblySteps.tsx (the scroll machinery)
- Track height `calc(N * 62vh + 100vh)` (N = 7). `.asm-sticky` is `position: sticky`; JS centres it on screen via
  `top` (never under the nav: min 76px, 64px ≤ 640px wide).
- `reading` = 0…1 through the pinned track. Active step = `floor(reading * N)`. Progress bar: 7 segments
  (`data-fill` scaleX), gap between the two groups (`data-gap`), "N remaining" / "Final step" text.
- Rover progress `p` eases toward `reading` (time constant 0.18s; reduced motion = instant). **Assembly follows
  scroll both ways** (scroll up = takes apart).
- Panel: all 7 steps stacked in one grid cell (tallest sets the height, no jump); states in/out/sizer with staggered
  `.asm-rise` entrance and a short accent glow (`data-flash`) on each step change. Screen readers get an `sr-only` list.
- Layout: viewport ≥ `SIDE_BY_SIDE = 980px` → panel floats left (340px wide, vertically centred) and the rover's
  framing is shifted right by `(panel width + 48) / 2` via `rover.shift(px)`; below that the panel sits under the canvas.
- Performance: `import("./rover")` only when the section is within one screen (IntersectionObserver rootMargin 100%);
  scroll listener only while near the screen (rootMargin 25%); theme changes via MutationObserver on `<html class>`.
- Figure aria-label: "Fig 03: a six-wheel planetary exploration rover in an exploded engineering view that assembles
  as you scroll, beside the OpenPlan story."

### rover.ts (the model)
- API: `mountRover(host, { dark })` → `{ set(progress 0..1), theme(dark), shift(px), dispose() }`.
- Axes: x forward (front at +x), y up, z = rover's left. Ground y = 0.
- **Concept:** every part is built once at its ASSEMBLED mount point (`home`); its exploded position is
  `home + off` (offset along its mounting axis). `set(p)` interpolates each part with its own time window, so the
  exploded view lines up like a CAD/engineering drawing. Craft rules taken from the **Anatomy skill**: real detail,
  crisp outlines, explode along mount axis with dashed guide lines, one accent colour for moving parts, calm easing,
  render only when something changes.
- `part(name, home, off, order, spin?)` creates a group; `add(geometry, material, at, rot, edges)` adds meshes with an
  `EdgesGeometry` outline (threshold 30°). `beam()` = rounded box between two points. Helpers `box`, `rbox`
  (RoundedBoxGeometry), `cyl(r, len, axis)`.
- **Materials** (MeshStandardMaterial, polygonOffset so outlines sit cleanly): paint `#f1efeb` matte white,
  alu `#b9b4ac` metal 0.85, dark `#2f2d2c` graphite, rubber `#1d1b1a`, rim `#9a958e`, lens `#141218`, gold `#c8a15a`
  (defined, unused), cells = canvas texture 6×6 indigo solar cells (`#1f3f8c → #102459`) with silver bus bars.

- **Guide lines:** dashed `LineDashedMaterial` from each part's mount to its current position; fade out as the part
  arrives (`opacity 0.55 * min(1, k*3)`).
- **Accent while moving:** each part's outline colour lerps idle → accent by `sin(π·e)` while it travels
  (light: idle `#57534e` → `#4f46e5`; dark: `#a8a29e` → `#818cf8`), opacity up by 0.45.
- **Studio:** HemisphereLight (0.9; 0.75 dark / 0.95 light), key DirectionalLight 2.3 at (4,9,5) with 2048 soft
  shadows, warm fill 0.55 at (−5,3,6), cool rim 0.9 at (−6,5,−6); RoomEnvironment via PMREM at intensity 0.6;
  ACES filmic tone mapping, sRGB; transparent background (the rover floats on the page, no card).
  Note: `shadowMap` is on and meshes cast/receive, but there is **no floor mesh** in the code, despite the comment
  "invisible floor that only catches soft shadows".
- **Renderer:** WebGLRenderer antialias + alpha, pixel ratio ≤ 1.75, canvas `touch-action: pan-y` (vertical swipes
  still scroll), cursor grab.
- **Camera:** PerspectiveCamera fov 24, one fixed view direction `(1.0, 0.55, 1.12)`; **the model turns, the camera
  only dollies.** Auto-fit: each part's 8 home-pose bbox corners are cached; on every change they are taken at the
  parts' current positions, at yaws −0.35/0/+0.35, projected on the camera axes, and the distance solved so they fill
  `0.9 − 0.04·progress` of the usable viewport (exploded fills 90%, built slightly less). `shift(px)` uses
  `setViewOffset` to move the framing right for the side panel.
- **Motion:** yaw = scroll turn (−0.35 → +0.35 with eased progress) + user drag (±1.05 rad, horizontal only,
  0.006 rad/px) + a gentle sway `0.16·sin(t/2600ms)` once fully built (not with reduced motion). Render loop only
  runs while something changes or the built rover is swaying, and only while on screen (IntersectionObserver).
- Dev only: `window.__roverScene` exposes the scene for console inspection.
